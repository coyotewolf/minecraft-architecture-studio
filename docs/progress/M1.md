## Limitations and exclusions

- M2–M10 are not implemented. The UI remains the runnable M0 empty-project shell; 3D/2D editing, materials aggregation, construction tracking, storage and AI are not available.
- No new M1 browser/editor interaction was claimed. M0 browser startup evidence remains historical; M2 must execute real browser camera/geometry/picking tests.
- State domains are validated, but physics/support, redstone, waterlogging requirements, fences/walls neighbor simulation and in-game placement are not. Conditional multi-stage `pitcher_crop` is rejected by model ingress pending a specific rule.
- Inventory metadata is conservative. Unknown mappings and state-dependent quantities remain unresolved. Same-ID base items do not prove complete construction costs or survival obtainability. M6 owns accurate aggregation and progress reconciliation.
- Whole-snapshot parsing preserves saved provenance. Import merges retain existing UID creation/modification history and stamp the transaction; new imported records retain their saved metadata. Metadata is not an authenticated claim of real-world observation.
- Bounds: 50k cells, 25k logical pairs, 10k combined changes per transaction and 32 MiB imported JSON. Large-model performance and peak memory are unmeasured. Full-state validation is linear and history is currently uncapped/in-memory. Large exports can exceed the import budget; M7 must reconcile full-project backup size/budgets before exposing backup UX.
- Critical branch coverage is not instrumented; no claim of meeting the 90% target.
- Direct Git clone and online npm access remain blocked in this environment. No credentials were extracted, no network policy was changed, no Minecraft process or game export was tested.
- No Higgsfield generation/upload/job or other paid call was made.
